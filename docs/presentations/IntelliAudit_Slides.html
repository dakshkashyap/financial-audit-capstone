Problem Statement · Paper 1 of 3

AuditBench — the benchmark we improve on

Automating Financial Statement Audits with Large Language Models — arXiv:2506.17282, UIUC + Stevens Institute, AAAI Workshop 2025.

Setup

  • 1,856 real S&P 500 financial statements
  • Exactly one injected error per table (or several, in the multi-error split)
  • Each table paired with a transaction narrative — the ground-truth of what actually happened
  • GPT-4 / GPT-3.5 must judge, classify, localize, explain, cite, and rewrite — in one prompt

Four error types (the whole task)

  • Numerical Error — a value was changed
  • Missing Row — a row was deleted
  • Redundant Row — an extra unsupported row was added
  • Misclassification — a real row placed in the wrong section

Problem Statement · Paper 2 of 3

FinAuditing — why citation can't be learned end-to-end

arXiv:2510.08886 · The Fin AI · Columbia · McGill · Cardiff · SIGIR 2026

What it is

  • Benchmark built from real XBRL filings — 4,545 official DQC error messages, 372 companies
  • Defines FinSM: map a line-item label → its correct us-gaap: taxonomy concept, over an 18,000-concept space
9–13%

This is exactly the row→concept mapping our citation pipeline needs. A 9–13%-accurate mapper would collapse everything built on top of it — this is why mapping in IntelliAudit is deterministic, not learned.

The Thesis

The 4.1% success rate is an architecture problem, not a model problem.

We hold the model fixed throughout this entire project — claude-opus-4-6 everywhere — and prove with a controlled ablation that separating arithmetic, citation, and explanation is what moves every headline number.

Architecture

One integration point per stage

# Stage 0 — deterministic gate finding = combine_findings(stage0a.verify(item), stage0b.check(item)) # → None (abstain) OR Finding(error_type, problematic_entry, # correct_value, stated_value, source, detail) # Full deterministic pipeline (Stage 0 + EDGAR + Stage 1) record = run_pipeline(item, TaxonomyGraph()) # record.abstained -> True: no proof yet, route to Stage 2 LLM # record.verified_consistent -> True: math checks out (anti-over-audit signal) # record.citation_primary / .citation_candidates -> grounded citations for Stage 2

When candidates are ambiguous, the system abstains to a human-review queue rather than forcing a guess — following AgentAuditor's finding that a forced choice from weak evidence is worse than declining to choose.

A strong model, over-auditing clean statements

Why this matters more than it looks

  • Not a parsing bug — the model performs real reasoning (footing checks, reconciliation) and finds numbers that look wrong
  • AuditBench's headline table never surfaces this — Success Rate is reported only on the error splits
  • A compliance system that cries wolf 50% of the time is unusable, no matter how good it is at catching real errors
  • This finding redirected the entire project.

Stage 0A · SymPy · $0

Arithmetic Verifier

Input → Output

  • In: parsed table (leaves + subtotals) + transaction "oracle"
  • Out: Finding or abstain

What it does

  • Recomputes every subtotal from its leaves (SymPy — symbolic, exact, cannot hallucinate)
  • Cross-references each stated value against the transaction oracle
  • Reports Numerical Error (broken leaf + correct value) and Missing Row (transaction-described row absent from the table + re-insertion position)

Why it matters for the paper's own bottleneck

GPT-4's Error Row EM = 0.737 — it hunted across 30-row tables and found the right row ~74% of the time. After Stage 0, the model is told which row failed and by how much when the gate fires. It confirms, it doesn't search.

Stage 0B · Pure Python · $0

Equation Checker

Structural identities checked

  • Assets = Liabilities + Equity
  • Sales − COGS = Gross Margin; Gross Margin − OpEx = Operating Income
  • Operating + Investing + Financing cash flow = Change in Cash

Localizes

  • Redundant Row — extra row inflates a subtotal, no transaction support
  • Misclassification — a real row present, but a subtotal is over by exactly its value while another is short by the same amount
  • These are not probabilistic — a violation is definitionally a structural error

Stage 0 · Design

Six principles that made it precision-first

  • Corroboration anchoring — fire only when a subtotal is off by exactly the implicated row's value
  • Magnitude-aware comparison — ignores sign + 0.5% rounding noise between narrative and table
  • Positional subtotal alignment — order, not label text (label matching was only ~64% reliable)
  • Injector-noise cleanup — strips HTML comment markers & quote-wrapping the dataset leaves in cells
  • Unique-label + index guard — avoids ambiguous-label collisions (e.g. Basic vs. Diluted EPS)
  • Abstain by default — multiple/ambiguous candidates → None, never a guess

Stage 1 · Taxonomy Graph

Citation by graph traversal, not recall

What it is

  • The FASB US-GAAP 2023 reference linkbase — every concept carries its governing ASC citation as metadata
  • Concept → citation is a graph walk, read verbatim from FASB's own published data
  • Parent fallback: if a leaf has no citation, walk up the graph — no leaf ever returns blank

Why this fixes a 26.2% memory test

GPT-4 tries to recall "ASC 210-10-45-1" from training and fails 74% of the time. Here, the answer is attached to the node as data — the model never recalls anything.

What "ceiling" means and why it matters

  • Even a hypothetically perfect Stage-2 LLM, always picking the best candidate the graph offers, could only reach 28.3%
  • The correct topic simply wasn't in the candidate set 72% of the time
  • Coverage is a vanity metric. We stopped reporting it alone.

Stage 1 · Root Cause & Fix

Presentation topics vs. subject-matter topics

The diagnosis

  • The FASB linkbase attaches presentation topics (210 Balance Sheet, 852 Reorganizations, S99 SEC-staff) to face-of-statement concepts
  • AuditBench actually cites subject-matter topics (330 Inventory, 350 Goodwill, 606 Revenue…) ~43% of the time
  • AuditBench's own GT is also version-inconsistent — mixes superseded (225, 605) with current (220, 606) topics

The fix — concept_citation.py

  • Subject-matter rules (regex over concept name) → presentation fallback → taxonomy graph pick, in priority order
  • UNION candidate set {subject ∪ presentation ∪ taxonomy arcs} fed to Stage 2 — the LLM selects, never invents
  • Version-family normalization (225→220, 605→606) — a fairer "is this citation right today" metric

Stage 2 · Focused LLM · ~$0.005/audit

The only stage that touches a language model

What it's handed (never derives itself)

  • A verified-consistent flag — "the math already checks out; don't invent a numerical error"
  • Concrete footing evidence, if any subtotal mismatch was found
  • A per-row grounded citation candidate list — it selects, never recalls from memory

System prompt design

  • Defaults to "Correct"
  • States explicitly: over-flagging a clean statement is "the single most common and most penalized mistake"
  • Same model as the baseline (claude-opus-4-6) — architecture is the only variable

Stage 3 · Deterministic Reviser

Design target vs. what's built today

Design target

  • SymPy recomputes every downstream subtotal/total after a correction — from the arithmetic definition, not the LLM's suggestion
  • Pydantic + Instructor enforce schema: valid error type, a citation that matches a real taxonomy reference, re-prompt until valid

What's implemented today honest gap

  • A narrow stub: for Numerical Error findings, a direct string substitution of the value in the table text
  • Full cascade recompute for structural edits (missing/redundant/misclassified rows) — not yet wired
  • Schema enforcement — not yet wired

Called out explicitly in the roadmap, not glossed over.

The Keystone Result

Architecture ablation — zero new LLM calls

A — LLM alone (baseline)50.0% (FP 50%)97.3%99.3%

A purely deterministic veto — zero new tools, zero new LLM calls — cuts the LLM's clean-table false-alarm rate in half (50% → 28.7%; 32 of 75 false alarms removed).

Honest cost, same breath: single-error recall drops 97.3% → 85.3% — ~13% of real errors leave no arithmetic trace and get a false all-clear. Arithmetic consistency is necessary but not sufficient for "correct."

The Strongest Scientific Finding

You cannot ask an LLM to stop over-auditing

Baseline (no mitigation)
50%
Conservative prompt alone
61%
Deterministic veto (symbolic layer)
28.7%

A prompt that simply listed the error types conservatively made false alarms worse, not better. Only giving the symbolic layer hard authority to override the LLM worked. This is direct, controlled evidence for the neuro-symbolic thesis.

Scientific Honesty

What we tried and reverted

  • Fuzzy label matching to raise Stage 0 coverage — coverage 0.38→0.49, but Type-EM-among-fired collapsed 0.947→0.662. Reverted.
  • Aggressive subtotal-tamper detection as a primary finding caused type mislabels — demoted to a weak fallback signal.
  • Early missing-row detection without corroboration flooded false positives before we added the subtotal-anomaly requirement.
  • Label-based subtotal matching (~64% reliable) replaced by positional alignment (near 100%).
  • Prompt-only conservatism for over-auditing raised false alarms to 61% instead of lowering them.
  • Raw taxonomy ranking let SEC-staff junk topics (S99, 852, 235) win over the correct subject topic — fixed by the subject/presentation split.

Limitations & Roadmap

What's next

Known limitations

  • Stage 0 coverage intentionally partial (~38–40%) — by design, not accident
  • Live XBRL route only helps the clean split (error tables strip company identity)
  • Citation ceiling (33–41%) is capped partly by AuditBench's own GT ambiguity
  • Stage 3 is a partial stub — full cascade recompute not yet wired

Roadmap, ranked by leverage

  • Tighten verified_consistent to cut the ~13% false all-clears
  • Make the veto type-aware — only override claims arithmetic can refute
  • bge-large embedding retrieval over the SEC-recovered concept set
  • Finish Stage 3's full SymPy cascade + schema validation
  • Multi-agent Auditor → Defender → Judge loop
  • Cross-benchmark validation on FinAuditing's real XBRL filings
