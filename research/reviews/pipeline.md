# Independent pipeline audit

This review inspects executable code and recomputes existing JSON predictions; it does not rely on README performance claims. Source snapshots are `daksh/ifrs-pipeline` at `4a622e0bd39e19c3a0d6fe6033e14854b107d983` and `irvin/citation-full-asc` at `159ae080dcddedf4a9cee9c5f831bb624d113782`. Machine-readable evidence, artifact hashes and counts are in `pipeline.json`; `pipeline.probe.py` reproduces the archived calculations without model calls.

The supplied branches contain no frozen run corresponding to the team's reported **12% full citation**. That number needs its prediction file, exam/key hashes, exact denominator and scoring configuration before it can be reconstructed. One verified defect can depress an apparent recall number: the ASC exam runner skips non-citable labels when counting hits, then divides by all exam cases (`run_iab_exam.py:339–398`). On the checked-in 1,202-case dataset, only 492 cases are citable. A 12% all-case rate would equal about 29.3% on those citable cases **if that denominator defect caused this particular result**; this is a conditional illustration, not a recovered result.

These are agreements with historical, unvalidated answer text, not independently established accounting correctness. Many gold citations specify only a topic/subtopic, so full paragraph scoring has only 32 eligible single-error examples. The old `_one_to_one` type/row helper returns 100% when the gold error list is empty, even for a false alarm; those clean-split values must not appear as meaningful localization results. Existing Opus evidence is **4.6**, not 5.5. There is no basis here for claiming that a cheap model matches or beats Opus 5.5.

The legacy citation scorer (`core/metrics.py:104–125` in ASC, `:104–129` in IFRS) awards credit for substring overlap: `ASC 210` matches `ASC 210-10-45-1`, and the IFRS variant awards shared-standard credit to different paragraphs. The historical success rate also excludes citation altogether (`core/metrics.py:138–145` in ASC). These definitions explain why topic overlap, paragraph accuracy, and “success” cannot be used interchangeably.

## Inference boundaries and the apparent 100%

The current ASC exam entry point has a useful boundary: `to_item` passes only statement text, transactions, sheet type and company (`run_iab_exam.py:182–189` in the source snapshot), and opens the answer key after predictions (`:570–578`). I found no `rule_id` branch in its main prediction pipeline.

However, `axis_stage2.load_joined` reads gold error type and affected XBRL concept from the key (`:148–149`), and `principle_topic` consumes those fields (`:303–305`). Re-running its analysis gives **492/492 topic matches**, plus 659/710 correct abstentions on non-citable examples. This is an **oracle error-type/concept diagnostic**. Avoiding a `rule_id` lookup does not make it a blind deployed result. The distinct `stage0_principle_full` function uses predicted error type and a mapped predicted row (`:1034–1041`) and is the applicable deployable comparison.

Likewise, `stage1_citation_eval.py:200` selects the gold broken row, and `citation_mcp_agent/eval_agent.py:131–132` supplies gold error type plus a topic used only by explicit oracle mode. These can measure isolated retrieval/selection ceilings if labelled as such. They cannot substitute for end-to-end detection, localization and citation accuracy.

The current checked-in answer key differs materially from the dataset described in the feedback: both capstone branches contain 1,202 cases with 492 citable records; the supplied upstream IntelliAudit snapshot contains 14,963 cases with 6,388 citable records. Recomputed in-sample **topic** majority shares on the smaller current key are 52.24% by statement and 64.02% by error type × statement, rather than the earlier feedback's values. These are distribution diagnostics fitted to the same key, not held-out predictive baselines. Fixed company-cluster splits and train-only prior fitting remain necessary.

## Concrete repairs in the cleaned branch

The merged branch retains the IFRS namespace/grammar and the ASC branch's full candidate plumbing, with these repairs:

- Strict `em_citation_exact` and separate `em_citation_topic` helpers require paragraph equality for full credit. The legacy prefix helper remains explicitly labelled to preserve old results. Incomplete first predictions still consume top-1 rank.
- Stage 2 checks every error against the localized row's exact paragraph candidates. Invalid/missing/topic-only picks become null, with `Raw Standards Citation` and a validation reason retained. It does not silently replace a failed model answer with an arbitrary candidate.
- Both prompts permit citation abstention. Reference membership establishes provenance, not applicability to the claimed accounting defect.
- Partial arithmetic consistency no longer erases model findings by default. Hard veto additionally requires an explicit complete error-absence certificate; existing callers have none. Prompt wording no longer claims that passing two checks proves the absence of every numerical/missing-row error.
- Numeric repair targets the unique identified row and verifies its entire old value cell. Repeated amounts in another row or a header remain untouched.
- IFRS enrichment retains actual linkbase paragraph codes, instead of collapsing them to IAS/IFRS standard names. The merged pipeline bypasses ASC normalization for IFRS codes.
- The ASC exam runner uses citable-only citation denominators, reports unsupported citations on non-citable cases, preserves unverified judgments, reports joint detection/type/row accuracy, retains raw Stage 2 output/errors, and respects requested sample sizes below or not divisible by three.
- The deterministic parser now accepts current upstream `[Label] description: +amount (increase); description: −amount (decrease)` evidence. It strictly requires signed well-formed components, checks sign/direction agreement, sums decimals exactly before conversion, rejects ambiguous/partial lines, and excludes subtotal/reviewer prose. Labels reconcile uniquely without requiring original row IDs. The evidence is explicitly partial and synthetic, so matching amounts never certifies recognition/measurement correctness or universally clean statements.
- Deterministic outputs now require an explicit `citation_applicability_verified` flag before promoting a reference candidate to an actual governing citation. This flag defaults to false, and no current automatic checker establishes applicability or sets it true. Candidate codes and retrieval provenance remain hints for an independent Stage 2 decision. The public legacy `run_audit` API follows the same distinction.
- The retained historical ablation replay also preserves abstention and parse failure, requires item-index/table-hash agreement, includes missing/failed/misaligned predictions in the full selected-case denominator, and uses the same complete-certificate veto guard. Partial consistency cannot manufacture clean-control accuracy in that entry point.

Validation: 11 existing IFRS tests and 13 meaningful boundary regressions pass using the existing Python environment. Tests cover repeated-value repair, absent rows/candidates, preservation of raw invalid answers, multiple errors, IFRS paragraphs, oracle metadata removal, partial-consistency limits and citation denominators. No model API calls were made for this review. These repairs improve validity and behavior; **their effect on benchmark accuracy has not been established by the historical runs**.

An additional unpaid transfer diagnostic runs the legacy deterministic pipeline on the new frozen 48-case pilot using only public inputs and a forced-offline static taxonomy map. It abstains on **48/48**, detects **0/32** injected defects and supplies a full citation on **0/16** citable cases. The key is opened only after writing predictions. The new component-movement transaction narrative differs from the legacy `[Explanation]`/row-reference syntax, so this exposes parser/coverage incompatibility; it is not a full Stage 2 evaluation or a result for the proposed new architecture. Source/input/output hashes and explicit limitations are in `research/artifacts/pilot/legacy_local_offline_metrics.json`. Abstention remains abstention rather than being credited as a clean-statement decision.

After adapting that interface, a separate frozen `legacy_local_adapted` condition on the same 48 public inputs detects **6/32** defects (three numeric mismatches and three missing rows), with correct type and exact row on **4/32**, and full citation agreement still **0/16**. It abstains on 42/48, including all 16 controls. The two remaining localization mismatches concern missing-row successor numbering. This is a concrete $0 parser improvement, but the reconstructable synthetic components can leak clean amounts; it establishes neither realistic accounting evidence nor performance on hidden multi-hop fraud. The full repository suite now passes **64 tests**, including nine new signed-component behavioral regressions. New predictions and their code/data hashes are separate from the unchanged offline baseline.

That first adapted snapshot also exposed an unsupported `ASC 210-10-45-1` citation on a missing-row case: arithmetic proof had promoted a static taxonomy hint without establishing applicability. The final applicability gate removes that behavior. A third frozen condition, `legacy_local_adapted_verified_citation`, retains **6/32** detections and **4/32** joint type/row matches, while abstaining from citation on **48/48** cases, including all 32 non-citable cases. The condition name refers to a required verification gate; **no automatic applicability verifier exists or was run**. Full citation agreement remains 0/16. All earlier snapshots remain unchanged. Two applicability regressions and three historical replay regressions pass; the final repository suite, including the parallel research changes, passes **92 tests**.

## Remaining limitations before a publishable result

The deterministic primary selector still ranks paragraphs by completeness/lexicographic tie-breaking (`citation_select.py:80–102`), which cannot establish applicability. The taxonomy graph prioritizes all general topics over industry topics (`taxonomy_graph.py:308`) and uses CamelCase truncation as a purported parent (`:344`), rather than real semantic ancestry. Candidate lists cap at eight; measuring full graph coverage does not establish coverage of the list actually shown to the model. New studies must report both.

Resume caches hash only the table (`intelliaudit_runner.py:211–212`), and pipeline prediction reuse omits prompt, model, transactions, taxonomy and architecture hashes (`run_intelliaudit.py:93–100`). The old ablation also aligns predictions by list position (`pipeline_eval.py:67–69`). Use the new manifest-based harness, or rerun into a fresh output directory with immutable case IDs and full configuration hashes. The legacy cached files are historical evidence, not results of the repaired code.

The review does not establish that remaining benchmark paragraphs govern their associated defects, that supporting transaction narratives are realistic accounting evidence, or that detection performance generalizes beyond these generators. Those questions require accountant adjudication and source-level validation; better model selection alone cannot resolve them.

For the paper, the relevant cheap-model hypothesis is a **budgeted evidence and applicability selector with explicit abstention**, evaluated against one verified frontier comparator on identical inputs, with oracle tracks separated. Freeze expert-reviewed multi-hop cases and equal-budget evidence access first. Report full paragraph applicability, joint detection/localization/citation, evidence-path recovery, false citation rate, cost and failure rate. A small development cohort can expose failures and estimate token costs; 5–10 company clusters cannot establish broad superiority or population representativeness.
