**Date:** July 2026 · SFU Capstone Team Sync

## What We Agreed On

The AuditBench dataset has a fundamental problem — its "correct" citation answers were written by GPT-4, which means we are grading our system against AI-generated answers that do not always match real accounting standards. The team agrees: treat AuditBench as a baseline only, and move toward better data.

**Priority dataset going forward: AuditFlow + FinAuditing (FinMR)**
- AuditFlow uses 67 real XBRL filings pulled from SEC EDGAR — actual company submissions, not synthetic data
- FinAuditing / FinMR has a three-task structure with cleaner ground truth
- Both are accessible via public APIs

---

## What Is Wrong With AuditBench (Quick Summary)

| Problem | Impact |
|---------|--------|
| Citations written by GPT-4 | Ground truth is inconsistent — same error gets different citation numbers in different samples |
| Accounting rules from 2023 and earlier | Newer 2024 standards not reflected |
| No cross-table reasoning | Each statement audited in isolation, no consistency checks across balance sheet / income statement / cash flow |
| Synthetic transaction data | The "oracle" was generated by a model, not pulled from real company books |

## The Architecture We Are Building

Three agents connected through an MCP server. Each agent has one job.

```
                  ┌─────────────────────────────┐
                  │         MCP SERVER           │
                  │                              │
                  │  Taxonomy graph loaded once  │
                  │  Agents query it as a tool   │
                  │  Shared state between agents │
                  └────────┬──────────┬──────────┘
                           │          │
              ┌────────────▼──┐  ┌────▼────────────┐
              │ Junior Agent 1 │  │ Junior Agent 2  │
              │                │  │                 │
              │ Starts from    │  │ Starts from     │
              │ the rulebook   │  │ the filing      │
              │ "What should   │  │ "What did the   │
              │  this be?"     │  │  company report?"│
              └────────┬───────┘  └────────┬────────┘
                       │                   │
                       └─────────┬─────────┘
                                 ▼
                      ┌──────────────────────┐
                      │    Senior Agent      │
                      │                      │
                      │ Reads both reports   │
                      │ Resolves disagreement│
                      │ by evidence strength │
                      │ Outputs final verdict│
                      └──────────────────────┘
```

The MCP server wraps the taxonomy graph — a structured map of accounting concepts and how they relate (cash flow ↔ revenue, assets ↔ liabilities, etc.). Agents call it to look up rules rather than recalling them from memory.

## Dataset Access — Confirmed

Both datasets are publicly available, no API key required.

**FinMR (use this first):**
```python
from datasets import load_dataset
ds = load_dataset("TheFinAI/FinMR")   # 332 rows, 4.8MB, free
```

**AuditFlow's 67 cases:**  
Not a separate download. AuditFlow used FinMR metadata (ticker, concept, period) and re-fetched the raw XBRL filing from SEC EDGAR for each row. We do the same:
```python
# For each FinMR row → GET https://data.sec.gov/api/xbrl/companyfacts/CIK{number}.json
# Free, public, no key needed
```

Ground truth in FinMR is produced by a deterministic DQC validator — not written by a human or GPT-4. This is why it is more reliable than AuditBench.
